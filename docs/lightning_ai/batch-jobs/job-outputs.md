# Job outputs[](#job-outputs)

Jobs often produce output files such as checkpoints, images, or logs. These artifacts are automatically managed and aggregated by the Lightning platform, ensuring seamless access and organization.

# Access artifacts[](#access-artifacts)

Artifacts generated by jobs are persisted differently depending on the selected compute environment.

## Studio Jobs[](#studio-jobs)

All artifacts from jobs submitted with a studio environment are stored on the Teamspace drive. Artifacts include training logs, model checkpoints and a snapshot of the studio that was executed in the job. These outputs are automatically available and can be accessed by any Studio for further analysis or reuse in future workflows.

Access them in any Studio or other Studio jobs via the teamspace drive in the directory named ` /teamspace/jobs/<job_name> ` . Inside this folder are two subdirectories: ` snapshot ` and ` artifacts ` . The snapshot folder contains the a snapshot in time of your Studio at the exact time you submitted the job for exact versioning and reproducibility. The artifacts directory contains all artifacts generated by the respective job.

If you are using Pytorch Lightning, it stores all training artifacts in a directory named ` lightning_logs/version_<number> ` which will be located in the artifacts directory for the job. This directory contains the model checkpoints in the ` checkpoints ` directory, and a tensorboard training log file for the training run.
