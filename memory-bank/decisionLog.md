- [2026-10-13 18:26:41] **Export `.prproj` : masques natifs et flou gaussien repris depuis le `.ecproj` (COMPLET)**
  - **Contexte** : l'écriture Premiere (`scripts/MediaSolution-EC/tools/ecproj_to_prproj.py`, format relevé sur un projet Adobe de référence) ignorait les masques et les effets — dès qu'un masque était détecté dans le `.ecproj`, seul le `.aep` était produit. Or masques et `ec.blur.gaussian` sont les deux seuls cas réellement utilisés en post-production.
  - **Démarche** : relevé du format sur un projet Premiere **natif** (`W9 - … _9x16_mask_blur.prproj` : masque `AE.ADBE AEMask2` à 27 paramètres, flou `AE.Impact_Blur_FX` à 18 paramètres), codec du blob de tracé en round-trip **octet-exact**, puis trois passes de validation dans Premiere 2026 sur notre propre export, chaque échec étant diagnostiqué sur le fichier ré-enregistré par Premiere (témoin).
  - **Découvertes** : (1) le paramètre `Path` est un blob binaire dont le `BinaryHash` n'est **pas un checksum** mais une clé d'identité opaque non validée — sans elle Premiere ignore le payload (calque noir) ; on écrit les hashes Adobe pour les payloads constants et un hash déterministe dérivé du contenu pour les tracés calculés. (2) Le tracé se normalise par la taille **source** du média (espace du calque, comme AE), pas par la comp — un média 1920×1080 monté en 1080×1920 donnait un masque hors-champ. (3) Un masque est un **sous-composant de l'Opacité** du clip (opacité matérialisée, plus de `DefaultOpacity` sur la chaîne) ; le mode de masque est le paramètre « Blend Mode » (0 = Add), distinct de `Type`. (4) EffectCraft n'applique un masque que s'il est actif, de mode ≠ None et au tracé **fermé** (`crates/render/src/masks.rs`) : un masque au tracé ouvert (masques vides non dessinés, fréquents dans les `.ecproj`) ne découpe rien côté EC et ne doit donc pas être écrit, sinon le clip devient noir à tort dans Premiere.
  - **Décision** : écrire les masques « Add » non inversés (blob + `BinaryHash`, Position/Anchor au centre de la bounding-box, masque vide **fermé** en état par défaut Adobe `Type 0`) et le flou gaussien (`blurriness` → « Amount », `dimensions`/`repeatEdge` non repris → avertissement) ; appliquer **la règle d'applicabilité d'EffectCraft** pour décider quels masques écrire ; conserver le blocage projet par projet (raison précise, `--force` pour passer outre) pour tout le reste : mode ≠ Add, inversion, roto-bezier, feather non lisse, feather variable par points, motion blur, effet inconnu.
  - **Alternatives rejetées** : (1) masques en rôle « clip » (chaîne `SelectionComponents`) — le rôle « effet » sous l'Opacité est la forme que Premiere réécrit lui-même et la seule vérifiée en interactif ; (2) `BinaryHash` recalculé maison pour tous les payloads — la clé n'est pas validée, les hashes Adobe d'origine sont sûrs pour les payloads constants ; (3) écrire les masques ouverts — divergence garantie (noir dans PP, calque entier dans EC).
  - **Validation** : 14 tests dédiés (`tests/unit/test_ecproj_to_prproj_masks.py` : round-trip octet-exact, assemblage masque/blur, skip ciblé, normalisation source, masque vide, tracé ouvert/mode None) + suite unitaire complète au vert ; validation utilisateur dans Premiere 2026 sur le projet réel `PP - LRDP - Bernard Mabille (1)_9x16` (parcours noir intégral → un masque conforme + un calque noir → **paires correctes**). Comportement revérifié sur les sources **0.9.2** (règles d'application identiques, schéma `.ecproj` `2` inchangé, même modèle de masque) ; garde-fou de scripting headless toujours présent (mode bridge requis à l'étape 8).
  - **Trace** : `docs/audits/prproj-masques-premiere-2026.md` (référence de format et règles), `scripts/MediaSolution-EC/README.md`, `scripts/MediaSolution-EC/docs/COMPATIBILITY.md`.
